# Data Model: TRT-LLM POC End-to-End

**Phase**: 1 — Design  
**Feature**: `001-trt-llm-poc-end-to-end`  
**Date**: 2026-05-01

## Overview

This POC has no persistent database. All entities are in-memory Rust types for the
duration of a request, plus filesystem artifacts (engine files, model weights). This
document captures the Rust type model and the filesystem layout.

---

## Rust Types

### `Capability` (enum)

Represents the inference mode selected for a request. Determines which model and
endpoint are used.

```rust
pub enum Capability {
    Chat,     // General conversational LLM
    Code,     // Coding-focused LLM
    Caption,  // Vision-language model for image description
}
```

**Routing rules** (implemented in `capability.rs`):
- If `InferenceRequest.image` is `Some(_)` → `Caption`
- Else if `InferenceRequest.system_hint` contains `"code"` keyword → `Code`
- Else → `Chat`

**Validation**: `Caption` without an image field is an error; `Chat`/`Code` with an image
field use `Caption` routing instead (image presence takes precedence).

---

### `ModelRoute` (struct)

Binds a `Capability` to a serving endpoint and model identifier. Configured at client
startup from environment variables or a config struct.

```rust
pub struct ModelRoute {
    pub capability: Capability,
    pub endpoint_url: String,   // e.g., "http://localhost:8000/v1/chat/completions"
    pub model_id: String,       // Triton model name, e.g., "llama3-chat"
}
```

**Default routes** (from `TRTLLM_HOST`, defaults to `localhost:8000`):

| Capability | `model_id` | Endpoint |
|------------|-----------|----------|
| Chat | `llama3-chat` | `http://{host}:8000/v1/chat/completions` |
| Code | `qwen-coder` | `http://{host}:8000/v1/chat/completions` |
| Caption | `llava-caption` | `http://{host}:8000/v1/chat/completions` |

---

### `Message` (struct)

OpenAI-style message unit used in request payloads.

```rust
pub struct Message {
    pub role: String,     // "system" | "user" | "assistant"
    pub content: String,  // text content of the message
}
```

---

### `InferenceRequest` (struct)

The request payload assembled by the Rust client before sending to the endpoint.

```rust
pub struct InferenceRequest {
    pub id: String,                    // UUID v4, generated by client
    pub messages: Vec<Message>,        // conversation history (OpenAI format)
    pub image: Option<String>,         // base64-encoded image bytes (Caption only)
    pub system_hint: Option<String>,   // routing hint, e.g., "code"
    pub max_tokens: Option<u32>,       // default: 512
    pub temperature: Option<f32>,      // default: 0.7
}
```

**State transitions**:
1. Constructed by caller
2. Capability resolved via routing rules
3. Serialized to JSON (OpenAI `ChatCompletionRequest` schema)
4. Sent via `reqwest`
5. Response deserialized into `InferenceResponse`

---

### `InferenceResponse` (struct)

The structured result returned to the caller.

```rust
pub struct InferenceResponse {
    pub request_id: String,         // echoed from InferenceRequest.id
    pub capability: Capability,     // capability that was used
    pub content: String,            // generated text
    pub model_id: String,           // model identifier echoed from endpoint
    pub prompt_tokens: Option<u32>, // from endpoint usage field
    pub completion_tokens: Option<u32>,
    pub latency_ms: u64,            // measured by client (wall clock)
}
```

---

### `RequestLog` (struct, logging only)

Not a persistent entity — emitted as a structured tracing event after each request
completes. Maps to a single log line (JSON with `tracing-subscriber`).

```rust
// Emitted via tracing::info!(...)
// Fields:
//   request_id: String
//   capability: &str         ("Chat" | "Code" | "Caption")
//   model_id: &str
//   latency_ms: u64
//   prompt_tokens: Option<u32>
//   completion_tokens: Option<u32>
//   success: bool
//   error: Option<String>    (populated on failure)
```

## Entity Relationships

```
Capability (enum)
    └── resolved from InferenceRequest (via routing rules)
    └── selects ModelRoute

ModelRoute
    └── holds endpoint_url + model_id for one Capability
    └── used by LlmClient to construct the HTTP call

InferenceRequest
    ├── contains Vec<Message>
    ├── optionally contains image (base64)
    └── resolves to → Capability → ModelRoute

InferenceResponse
    └── produced from HTTP response + client-measured latency
    └── emits → RequestLog (tracing event)
```

## Validation Rules

| Field | Rule |
|-------|------|
| `InferenceRequest.messages` | MUST be non-empty |
| `InferenceRequest.image` | If present, MUST be valid base64; triggers `Caption` routing |
| `InferenceRequest.max_tokens` | If present, MUST be >0 and ≤4096 |
| `InferenceRequest.temperature` | If present, MUST be in [0.0, 2.0] |
| `ModelRoute.endpoint_url` | MUST be a valid URL parseable at startup |
| `InferenceResponse.content` | Empty string is a valid (if degenerate) response; not an error |
